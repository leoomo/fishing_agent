## 🔧 模块职责划分

### 1. **工具层 (lure_tools.py)**

**职责**：
- 提供LangChain工具接口
- 参数验证与规范化
- 调用业务逻辑模块
- 异常处理与错误提示

**接口设计**：
```python
@tool
def query_lure_equipment(
    equipment_type: str,
    specifications: Optional[Dict[str, Any]] = None,
    query_mode: str = "recommend"
) -> str:
    """
    路亚装备智能推荐

    Args:
        equipment_type: 装备类型（鱼竿/渔轮/鱼线等）
        specifications: 规格要求（预算/硬度/品牌等）
        query_mode: 查询模式（recommend/compare/package）

    Returns:
        Markdown格式的推荐报告
    """
```

**依赖关系**：
- 依赖业务逻辑层的所有模块
- 被LangChain Agent调用

### 2. **推荐算法层 (recommender.py)**

**职责**：
- 实现推荐算法
- 计算匹配度评分
- 处理装备组合逻辑
- 生成对比分析

**核心类**：
```python
class LureRecommender:
    def recommend(
        self,
        equipments: List[Dict],
        user_specs: Dict
    ) -> List[Dict]:
        """推荐装备"""

    def calculate_match_score(
        self,
        equipment: Dict,
        user_specs: Dict
    ) -> float:
        """计算匹配度"""

    def recommend_package(
        self,
        budget: float,
        user_level: str
    ) -> Dict:
        """推荐套装"""
```

**配置文件**：
```python
RECOMMENDATION_CONFIG = {
    "weights": {
        "price_match": 0.35,
        "spec_match": 0.35,
        "brand_reputation": 0.15,
        "user_level": 0.15
    },
    "filters": {
        "max_price_deviation": 0.2,
        "spec_tolerance": {
            "length": 0.3,
            "power": 1
        }
    }
}
```

### 3. **数据获取层 (data_fetcher.py)**

**职责**：
- 统一数据获取接口
- 多数据源管理（API/爬虫/本地）
- 数据质量验证
- 降级策略

**核心类**：
```python
class LureDataFetcher:
    def __init__(self, source_type: str = "api"):
        """初始化数据源"""

    def fetch_equipment(
        self,
        equipment_type: str,
        filters: Dict
    ) -> List[Dict]:
        """获取装备数据"""

    def _fetch_from_api(self, ...):
        """从API获取"""

    def _fetch_from_scraper(self, ...):
        """从爬虫获取"""

    def _fetch_from_local(self, ...):
        """从本地数据库获取"""
```

**降级策略**：
```
1. 尝试API获取 (timeout=2s)
   ↓ 失败
2. 尝试爬虫获取 (timeout=5s)
   ↓ 失败
3. 使用缓存数据（标注"可能过期"）
   ↓ 缓存未命中
4. 使用本地静态数据
   ↓ 无匹配数据
5. 返回友好错误 + 推荐替代查询
```

## 🔄 数据流设计

### 场景1：单装备推荐

```
用户查询："推荐ML调路亚竿，预算300元"
   ↓
LangChain Agent（LLM理解意图）
   ↓ 提取参数
equipment_type = "鱼竿"
specifications = {"预算": 300, "硬度": "ML"}
   ↓ 调用工具
query_lure_equipment(equipment_type, specifications)
   ↓
data_fetcher.fetch_equipment("鱼竿", {"预算": 300})
   ↓ 查询数据库
database.execute("SELECT * FROM equipment WHERE category=? AND price_min<=?")
   ↓ 返回候选装备
[装备1, 装备2, ..., 装备10]
   ↓
recommender.recommend(equipments, {"预算": 300, "硬度": "ML"})
   ↓ 计算匹配度
[装备3(92分), 装备7(88分), 装备2(85分)]
   ↓
formatters.format_recommendation(top3, user_specs)
   ↓ 生成报告
Markdown格式推荐报告
   ↓
返回给用户
```

### 场景2：装备组合推荐

```
用户查询："新手入门套装，竿+轮+线，预算1000元"
   ↓
LangChain Agent
   ↓ 提取参数
query_mode = "package"
specifications = {"预算": 1000, "用户水平": "新手"}
   ↓ 调用工具
query_lure_equipment(equipment_type="套装", specs, query_mode="package")
   ↓
recommender.recommend_package(budget=1000, user_level="新手")
   ↓ 查询各类装备
鱼竿候选 = fetch_equipment("鱼竿", {"预算": 400})
渔轮候选 = fetch_equipment("渔轮", {"预算": 350})
鱼线候选 = fetch_equipment("鱼线", {"预算": 250})
   ↓ 兼容性检查
compatible_combos = check_compatibility(鱼竿, 渔轮, 鱼线)
   ↓ 性价比排序
best_combo = sort_by_value(compatible_combos)[0]
   ↓
formatters.format_package(best_combo)
   ↓
返回套装配置报告
```

## 🎯 技术选型理由

### 1. **SQLite（而非PostgreSQL）**

**理由**：
- ✅ 与项目fishing-agent保持一致
- ✅ 零配置部署（单文件数据库）
- ✅ 数据规模小（100-500款装备，<5MB）
- ✅ 读多写少场景（WAL模式完美匹配）
- ✅ 性能足够（支持50+ QPS）

**何时迁移PostgreSQL**：
- 数据量 > 10000款
- 并发量 > 200 QPS
- 需要复杂查询（多表JOIN、全文搜索）

### 2. **原生API（而非ORM）**

**理由**：
- ✅ 符合项目"零抽象"原则
- ✅ 零外部依赖（标准库sqlite3）
- ✅ 性能最优（无抽象层开销）
- ✅ 调试简单（SQL直观可见）
- ✅ 预留扩展点（DatabaseAdapter接口）

**换库成本**：
- 重写SQL语句（3-5天工作量）
- 但那时对业务已很熟悉，重写=优化机会

### 3. **规则算法（而非机器学习）**

**理由**：
- ✅ 数据量不足（100款装备训练ML过拟合）
- ✅ 可解释性强（用户知道为什么推荐）
- ✅ 可配置调优（A/B测试权重）
- ✅ 无需GPU（降低部署成本）

**何时引入ML**：
- 数据量 > 10000款
- 有用户行为数据（点击/购买）
- 需要个性化推荐

### 4. **LLM做NLP（而非工具内正则）**

**理由**：
- ✅ LLM理解自然语言更准确
- ✅ 工具代码更简洁
- ✅ 易于扩展新参数类型
- ✅ 避免维护复杂正则表达式

**架构**：
```
LLM（负责）：
- 理解用户意图
- 提取参数（预算、品牌、硬度等）
- 选择查询模式（推荐/对比/套装）

工具（负责）：
- 数据检索
- 推荐计算
- 结果格式化
```

## ⚠️ 架构约束

### 1. **单一职责原则**
- 每个模块只负责一件事
- 推荐算法不关心数据来源
- 数据获取不关心推荐逻辑

### 2. **依赖倒置**
- 工具层依赖抽象接口，不依赖具体实现
- 可以替换任意模块而不影响其他模块

### 3. **开闭原则**
- 对扩展开放（新增装备类型、数据源）
- 对修改封闭（核心逻辑稳定）

### 4. **最小惊讶原则**
- API设计符合直觉
- 错误提示清晰友好
- 与项目现有风格一致
