## 🎯 设计原则

### 1. **与项目保持一致**
- ✅ 使用SQLite（与fishing-agent一致）
- ✅ 原生API，无ORM（零抽象原则）
- ✅ 同步优先（简化架构）
- ✅ 零配置部署

### 2. **渐进式实现**
- ✅ 从10款数据开始验证功能
- ✅ 逐步扩展到100+款
- ✅ 按需补充数据，避免过度投入

### 3. **可维护性优先**
- ✅ 模块清晰分离（数据/算法/格式化）
- ✅ 配置化驱动（权重可调整）
- ✅ 完整测试覆盖

### 4. **用户体验为本**
- ✅ LLM做NLP，工具专注推荐
- ✅ 专业报告格式（需求分析+推荐+建议）
- ✅ 友好错误提示

---

## 📊 技术栈总结

| 层级 | 技术选型 | 理由 |
|------|---------|------|
| **数据存储** | SQLite + WAL | 与项目一致，支持并发读 |
| **数据库访问** | 原生sqlite3 | 零依赖，性能最优 |
| **数据获取** | 爬虫 + API | 渐进式，可降级 |
| **推荐算法** | 规则算法 | 可配置，可解释 |
| **工具框架** | LangChain 1.0+ | 项目标准 |
| **测试框架** | pytest | 项目标准 |
