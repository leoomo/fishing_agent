## 🔧 工具层设计（4个工具）

### 工具设计原则

**核心理念**：按用户意图分类，边界清晰，LLM易于选择

| 工具 | 核心意图 | 触发关键词 | 使用场景 |
|------|---------|-----------|---------|
| `recommend_equipment` | 买什么 | 推荐、买、选、预算、性价比 | 购买决策 |
| `compare_equipment` | 比哪个 | 对比、比较、区别、VS、哪个好 | 多产品比较 |
| `lookup_fishing_knowledge` | 学什么 | 什么是、怎么用、习性、教程 | 知识学习 |
| `identify_from_image` | 看什么 | 图片、识别、这是什么 | 视觉识别 |

### 1. **recommend_equipment（装备推荐）**

**职责**：根据用户需求推荐最合适的装备

```python
@tool
def recommend_equipment(
    equipment_type: str,
    budget: Optional[float] = None,
    specifications: Optional[Dict[str, Any]] = None,
    target_fish: Optional[str] = None,
    scenario: Optional[str] = None,
    user_level: Optional[str] = None
) -> str:
    """
    推荐路亚装备 - 用于购买决策

    当用户想要【购买建议】或【选择推荐】时使用。
    关键词: 推荐、买、选、预算、性价比、适合新手

    Args:
        equipment_type: 装备类型（鱼竿/渔轮/鱼线/拟饵/套装）
        budget: 预算金额（元）
        specifications: 规格要求（硬度/调性/速比等）
        target_fish: 目标鱼种
        scenario: 使用场景（水草区/深水/障碍区）
        user_level: 用户水平（新手/进阶/高手）

    Returns:
        Markdown格式的推荐报告（含产品图片）
    """
```

**数据流**：
```
用户: "预算500推荐ML调鱼竿"
  ↓
LLM提取参数 → recommend_equipment(equipment_type="鱼竿", budget=500, specifications={"硬度": "ML"})
  ↓
data_fetcher.fetch_equipment() → 获取候选装备
  ↓
recommender.recommend() → 计算匹配度评分
  ↓
formatters.format_recommendation() → 生成报告（含图片URL）
  ↓
返回Markdown报告
```


## 🎯 技术选型理由

### 1. **SQLite + Chroma（双存储架构）**

| 组件 | 用途 | 选型理由 |
|------|------|---------|
| SQLite | 结构化数据 | 精准查询、关联关系、事务支持 |
| Chroma | 向量数据 | 轻量嵌入式、与SQLite理念一致、无需服务器 |

**为什么不用pgvector？**
- ✅ 项目已使用SQLite，保持一致性
- ✅ Chroma是嵌入式向量库，零配置
- ✅ 数据规模小，无需PostgreSQL重量级方案

### 2. **Embedding模型选型**

| 模型 | 用途 | 选型理由 |
|------|------|---------|
| BGE-M3 | 文本向量化 | 中文支持好、开源免费、性能优秀 |
| AltCLIP | 图片向量化 | 中文多模态、开源、支持文图匹配 |

### 3. **图片存储策略**

```python
class ImageStorageAdapter:
    """统一图片存储接口"""

    def __init__(self, storage_type: str = "local"):
        self.storage_type = storage_type

    def save(self, image_data: bytes, path: str) -> str:
        if self.storage_type == "local":
            return self._save_local(image_data, path)
        elif self.storage_type == "oss":
            return self._save_oss(image_data, path)

    def get_url(self, path: str) -> str:
        if self.storage_type == "local":
            return f"file://{path}"
        elif self.storage_type == "oss":
            return f"https://oss.example.com/{path}"
```

**设计理由**：
- ✅ 当前使用本地存储，简单直接
- ✅ 预留OSS接口，未来无缝切换
- ✅ 统一接口，业务层无感知

### 4. **LLM做工具选择（而非工具内路由）**

**设计理由**：
- ✅ 4个工具边界清晰，LLM选择准确率高
- ✅ 工具职责单一，易于测试和维护
- ✅ 避免工具内部复杂的意图识别逻辑

## ⚠️ 架构约束

### 1. **分层依赖规则**

```
工具层 → 业务逻辑层 → 数据存储层 → 物理存储层
  ↓           ↓              ↓
只能向下依赖，禁止跨层或反向依赖
```

### 2. **数据一致性保证**

- SQLite与Chroma的数据同步由业务层负责
- 图片删除时需同时删除：物理文件、SQLite记录、Chroma向量

### 3. **工具选择清晰度**

- 每个工具的docstring必须包含明确的触发关键词
- 工具之间不能有功能重叠
- 模糊场景由`lookup_fishing_knowledge`的向量搜索兜底
