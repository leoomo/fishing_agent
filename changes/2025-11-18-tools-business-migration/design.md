# 迁移旧业务逻辑到新架构 - 技术设计

## 🏗️ 架构设计原则

### 1. 简化优先
- **直接使用LangChain @tool装饰器**: 避免额外的注册管理系统
- **最小化依赖**: 减少模块间的复杂依赖关系
- **扁平化结构**: 保持目录层次的简洁性

### 2. 模块化设计
- **单一职责**: 每个模块专注于特定的业务领域
- **松耦合**: 模块间通过明确的接口进行交互
- **高内聚**: 相关功能集中在同一模块内

### 3. 向后兼容
- **渐进式迁移**: 新旧架构并存，逐步过渡
- **回退机制**: 提供多层导入回退，确保系统稳定
- **API保持**: 保持所有现有工具的接口不变

### 模块职责划分

#### Basic Tools (基础工具)
**职责**: 提供通用的基础功能，不依赖特定业务

**设计要点**:
- 每个工具文件包含1-2个相关功能
- 使用简化的实现，避免复杂依赖
- 提供清晰的错误处理和用户友好的返回信息

#### Fishing Business (钓鱼业务)
**职责**: 完整的钓鱼相关业务逻辑

**分层设计**:
1. **Weather Layer (数据层)**:
   - 职责: 纯粹的天气数据获取
   - 输入: 地理位置和时间参数
   - 输出: 结构化的天气数据
   - 特点: 无业务逻辑，专注数据获取

2. **Advice Layer (分析层)**:
   - 职责: 钓鱼业务分析和建议
   - 输入: 天气数据 + 地理位置
   - 输出: 钓鱼评分、建议和推荐
   - 特点: 包含复杂的业务算法和规则

3. **Equipment Layer (推荐层)**: (预留)
   - 职责: 装备推荐和管理
   - 输入: 天气条件 + 目标鱼种 + 用户偏好
   - 输出: 装备推荐和使用建议
   - 特点: 个性化推荐算法

## 🔧 技术实现细节

### 1. 模块化拆分策略

#### 大文件拆分原则
- **按功能拆分**: 将大文件按功能特性拆分为小文件
- **保持独立**: 每个拆分后的文件应该可以独立工作
- **最小依赖**: 减少文件间的相互依赖

**示例**: `langchain_weather_tools_sync.py` (612行) 拆分:
```
原文件: langchain_weather_tools_sync.py
├── fishing/weather/weather_tools.py    # 5个天气查询工具
└── fishing/weather/fishing_tools.py    # 1个钓鱼推荐工具 + 辅助函数
```

#### 依赖关系管理
- **分层依赖**: 上层依赖下层，避免循环依赖
- **接口抽象**: 通过__init__.py提供清晰的导入接口
- **回退机制**: 提供多层导入失败时的回退方案

### 2. 导入策略设计

#### 多层导入机制
```python
# 示例: fishing/weather/__init__.py
try:
    from .weather_tools import (*)           # 优先: 新模块化文件
except ImportError as e:
    try:
        from tools.langchain_weather_tools_sync import (*)  # 回退: 原始文件
    except ImportError as fallback_e:
        def get_weather_tools():             # 最终回退: 空列表
            return []
```

#### 相对导入规范
- **同级导入**: 使用 `from .module import`
- **跨级导入**: 使用 `from ..parent.module import`
- **绝对导入**: 在必要时使用完整路径

### 3. 错误处理策略

#### 分层错误处理
1. **工具层错误**: 提供用户友好的错误信息
2. **模块层错误**: 提供模块级的降级机制
3. **系统层错误**: 确保系统整体的稳定性

#### 降级机制示例
```python
try:
    from .weather_tools import query_current_weather
except ImportError:
    try:
        from tools.langchain_weather_tools_sync import query_current_weather
    except ImportError:
        @tool
        def query_current_weather(place: str) -> str:
            return f"⚠️ 天气查询服务暂时不可用，请稍后重试"
```

### 4. 性能优化设计

#### 按需加载
- **延迟导入**: 只在需要时导入特定模块
- **工具分离**: 将独立工具分离到不同文件
- **缓存优化**: 保持现有的多级缓存机制

#### 内存管理
- **全局实例**: 对于重量级服务使用全局单例
- **资源释放**: 提供适当的资源清理机制
- **循环引用**: 避免模块间的循环引用
